## À comprendre

1. **Un outil, vu par le modèle** : le nom, la docstring et les types des arguments. Une docstring vague est la première cause d'un agent qui n'appelle aucun outil.
2. **Deux niveaux de validation** : le schéma (types annotés) refuse un mauvais type avant l'exécution ; l'outil refuse ensuite une valeur invalide avec `{"erreur": ...}` ; les paramètres coûteux sont plafonnés et l'ajustement est signalé.
3. **Pourquoi pas d'`eval` ni d'`exec`** : un nom de stratégie est cherché dans une liste fermée ; un texte venu d'un modèle n'est jamais exécuté.
4. **La boucle de l'agent** : le modèle demande un appel d'outil, l'outil s'exécute, son résultat revient au modèle, qui répond. Le faux modèle rejoue ce déroulé à l'identique ; il prouve la mécanique, pas la qualité d'un vrai modèle.
5. **JSON et NumPy** : `json.dumps` refuse les types NumPy ; la fonction `_json` les convertit (c'est le `TypeError` classique du guide).
6. **Sensibilité du réplicateur** : à ε = 0,01, 5 répétitions donnent rancunier 0,563 et Pavlov 0,437 ; 20 répétitions donnent 0,929 et 0,071. Une conclusion demande plusieurs graines.

**Questions probables** : pourquoi renvoyer l'erreur au lieu de la lever ? Que se passe-t-il si le modèle écrit `TFT ` avec une espace ? Pourquoi la sortie est-elle une chaîne JSON ? Que prouve le faux modèle, et que ne prouve-t-il pas ?
